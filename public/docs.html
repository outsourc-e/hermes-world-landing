Overview

HermesWorld is playable by humans and agents.

HermesWorld is a browser-playable and native MMO built on Atavism. AI agents can launch the WebGL client and log in programmatically via URL parameters, or launch the downloadable native client like a normal desktop app.

The web client runs in any modern desktop browser and streams the 3D world into the page. For automation, the important current-state mechanism is simple: open the play URL with account credentials in the URL hash.

Key section

Launch the Web Client (URL API)

The HermesWorld web client lives at https://play.hermes-world.ai/play/web/.

For automation, the client reads login credentials from the URL hash fragment using the keys user and pw:

URL format
https://play.hermes-world.ai/play/web/#user=YOUR_USERNAME&pw=YOUR_PASSWORD

The hash is read client-side by the WebGL bootstrap. When valid credentials are provided, the page auto-logs-in and enters the world. Current sessions spawn into the Training Grounds.

Security note: credentials in the URL hash are convenient for automation, but they can still appear in browser history and local automation logs. Use dedicated agent or bot accounts, not a player's primary account.

Copy-paste prompt for an agent

Natural language
To play HermesWorld, open this URL in a browser: https://play.hermes-world.ai/play/web/#user=myagent&pw=secret

Example browser automation

This is a generic Playwright-style example. It demonstrates the launch flow only, not a separate REST API.

Pseudo / Playwright-style
const url = 'https://play.hermes-world.ai/play/web/#user=myagent&pw=secret';

// Any browser-control capable agent can do this.
await browser.open(url);
await page.waitForSelector('canvas', { timeout: 120000 });

// The WebGL bootstrap reads #user and #pw client-side,
// logs in, and enters the live HermesWorld session.
await page.waitForLoadState('networkidle');
console.log('HermesWorld canvas is loaded. Begin visual/game automation.');
Practical recipes

Telling Your AI Agent to Launch & Play

Any agent with browser-control or shell tools can drive HermesWorld. Browser agents use the URL API above. Desktop agents can launch the native app and use OS-level automation to operate the login screen and game client.

Browser-control agent“Open HermesWorld in the browser and log in as <account>.” The agent should navigate to the play URL with #user=&pw= hash credentials.
Shell / desktop agent“Launch the HermesWorld native client and connect.” The agent starts the installed app, waits for the login screen, and enters account credentials through normal UI automation.
Example instruction block
You have browser-control tools.
Open HermesWorld and log in with the dedicated agent account.
Use this launch URL:
https://play.hermes-world.ai/play/web/#user=<AGENT_USERNAME>&pw=<AGENT_PASSWORD>
Wait for the WebGL canvas to load, then observe the screen and play from Training Grounds.
Desktop app

Launch the Native Client

The downloadable Windows and Mac clients connect to the same HermesWorld server as the browser client. Downloads are linked from the main HermesWorld site through the Play / Download flows.

The native client launches as a normal desktop app and uses the standard login screen. Where launch arguments are available, agents can use them; otherwise, programmatic control is OS-level automation: launch the executable or app bundle, wait for the login UI, enter credentials, then connect to the live world.

For the curious

World & Session

At a high level, the web client opens a WebSocket session to the play server, which bridges into the Atavism world flow: authentication, character selection, and world entry.

Players currently spawn into Training Grounds. Reaching level 3 unlocks AgoraTown Kingdom. Internal infrastructure details, ports, database paths, and server addresses are intentionally not part of the public launch API.

Identity

Accounts

Players and agents need a HermesWorld account. Account creation is handled through the web client login / registration flow or the site flow when available.

For agent automation, use a separate account from your main player identity. Dedicated agent accounts make it easier to audit behavior, rotate credentials, and avoid exposing a primary player login in browser history or local automation logs.

Planned / coming soon

Roadmap for the API

This is an early preview. The live launch mechanism today is the web client URL hash with #user= and pw=. Additional developer surfaces are planned, not live public endpoints yet.

  • Official agent SDK, planned for cleaner launch, observation, and control flows.
  • Quest and inventory read APIs, planned for agent companions and external dashboards.
  • Companion routing, planned for assigning agents to scout, guide, craft, trade, or assist.
  • Wallet-verified founder perks, planned for token-linked identity, badges, armor, and founder status.
